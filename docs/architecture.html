Agentic AI Registrar Office

A multi-agent system that acts like a university registrar office. It keeps five databases and answers students, professors, advisors and administrators. Each user only gets the information they're allowed to see.

System architecture

The Registrar coordinator can't read any data. It routes each request to one of four specialist agents, sending independent parts to several at once, and merges their answers. Specialists reach the data only through tools, and every tool goes through one service layer that checks the user's role.

Tools are filtered twice. Each specialist only gets the tools for its own area. Then any tool the logged-in role can't use is removed before the session starts. A student session, for example, has no Analytics agent at all.

One request, traced

This is a real run from testing, as Professor P01 (Dr. Alan Turing):

“What am I teaching this semester, how are my CS201 grades historically, and show me the CS101 roster.”

  1. Registrar splits the request into 2 independent jobs
    The schedule and roster go to Registration, and the grade history goes to Analytics. Both run at the same time.
  2. Registration calls professor_schedule
    Result: Fall 2026 sections CS201, CS310 and CS320, with 38 students enrolled in total.
  3. Registration calls class_roster(CS101)
    PermissionDenied: “You do not teach CS101 in Fall 2026.” The service layer refused it, so no prompt wording could get around it.
  4. Analytics calls course_grade_stats(CS201)
    The result only includes semesters P01 taught: 21 grades, an average GPA of 2.94, an A-rate of 28.6% and a fail-rate of 0%.
  5. Registrar merges both answers into one reply
    It shows the schedule and grade tables, explains why the roster was refused, and offers rosters the professor is allowed to see. Cost of the turn: $0.17.

Data model

These are the five tables from the project brief. A few columns were added so the features work: prerequisites for registration, an advisor for each student, and seat capacity and meeting times for schedules. A grade of NULL means the student is enrolled and the course has no grade yet.

Students

  • id S1001…S1060
  • name
  • major
  • advisor_id → Professors
  • entry_semester

Grades

  • student_id
  • course
  • semester
  • grade A … F, or NULL

Schedule

  • course
  • semester
  • professor_id
  • days · time · room
  • capacity (35)

Courses

  • code CS101…PHYS101
  • title
  • credits 3 or 4
  • prerequisites

Professors

  • id P01…P07
  • name
  • department

Registrar policies in the sample data

  • 42 creditsto graduate, with all 8 core courses and a GPA of at least 2.0
  • GPA < 2.0marks a student as at risk of dismissal. A GPA from 2.0 to 2.3 is probation watch
  • C- or bettercounts toward a prerequisite
  • 18 creditsis the most a student can take in one semester
  • Fall 2026is in progress, and registration is open for Spring 2027
